## Friction

The pinned Fallow 3.16 GitHub Action rejects a zero-finding dead-code baseline generated by the lockfile-installed Fallow 3.16 CLI with `baseline analysis identity is incompatible in: project_config_hash`. The same baseline passes the local type-aware audit and full-repo gate, and regenerating a standalone baseline on the PR merge ref produces the same local hash.

## Impact

The reporting Action cannot consume the committed exact baseline even though the authoritative local/CI CLI gate can. The repository must rely on the Action native base-snapshot attribution for PR reporting and keep exact project-wide baseline enforcement in its normal CI job.
